# Graphics: framebuffer, console, `/dev/fb0`, compositor, GUI programs

Code: `kernel/src/framebuffer.rs`, `kernel/src/drivers/{framebuffer_console,dev_fb0}.rs`, `kernel/src/memory/memtype.rs`, `hal::{memtype,fbdirty}`. Userspace: `userspace/src/bin/{compositor,panel,term,cpumon,textdemo,imgview}.rs`, crates `gui`/`vt`/`draw`/`text`/`img`. Plans: `docs/fb/`, `docs/gui/gui-plan.md`, `docs/gui/text-plan.md`, `docs/gui/perf-plan.md` (pending: 50 fps timer cap, AVX/compiler-flag candidates).

## Framebuffer (`Framebuffer`)

- **RAM shadow**: every primitive draws into a write-back RAM copy and marks a dirty rectangle.
  - `Framebuffer::flush` is **the only code that writes VRAM** (write-only, `sfence` at the end).
  - Outside a batch, each primitive flushes its own rectangle. `begin_batch`/`end_batch` (they nest) coalesce the flushes; the console wraps each `write` in one batch.
  - **Any new code that writes VRAM without going through `Framebuffer`'s primitives desyncs the shadow.**
  - If the shadow can't be allocated, the console runs in direct mode (`shadow:` in `/proc/fbinfo`).
- **Page flipping** (`attach_flip`, only with `gpu=scanout`, `docs/reference/gpu.md`): the VRAM side becomes two buffers and a `Scanout` (the display) that flips between them; the GOP mapping is never written again. The shadow stays the only thing drawn into; each buffer keeps a `DirtyRect` of what it has not received.
  - `flush` (primitives, console, `kalert!`, panic) copies to the *front* buffer (on screen, or the target of a pending flip) and marks the other stale.
  - `present(rects)` (`FBIO_FLUSH`): `Busy` while the last flip is pending; otherwise copies the other buffer's stale area plus `rects` into it and flips. The buffer on screen is never written by `present`.
  - Tested by `hw_tests::framebuffer_page_flip_writes_only_the_hidden_buffer` (RAM buffers, fake display).
  - The shadow starts `SHADOW_SKEW` bytes into its allocation: sharing the aperture's alignment caused TLB-slot collisions.
- **Write-combining**: `memtype::program_pat()` makes PAT entry 1 WC (`WB WC UC- UC WB WT UC- UC`), and `map_write_combining()` points the aperture at it. **Consequence: any mapping with `WRITE_THROUGH` set and `NO_CACHE` clear is WC, not write-through.**
- Always use `stride`, never `width`, for row offsets.
- Hot per-pixel loops: at `opt-level 0` with `build-std`, `write_unaligned` becomes a call with UB checks. Use aligned 32-bit stores and `memcpy` of whole scanlines (`fill_rect`, `blit_scaled`).
- `/proc/fbinfo` is the instrument panel: geometry, physical address, PTE PAT bits, `IA32_PAT`, the covering MTRR (MTRR and PAT reported separately, never combined), `mode`, `shadow`, `fb_wc`, `text_grid`, and per-primitive `diag::OpStat` (calls/bytes/cycles/min/max, plus `instrument_overhead`).
- On the Ryzen VRAM is across PCIe and reads are very slow; QEMU hides every framebuffer performance problem. Measure on metal (`docs/fb/console-perf.md`).

## Text console (`FramebufferConsole`, `/dev/fb`)

- ANSI parser plus the renderer `render_bytes`.
- Font: Noto Sans Mono from the `noto-sans-mono-bitmap` crate (≥0.3; 0.2 clips descenders), antialiased, size chosen from the screen height by `init_font` (1080p → 24 px).
- Supports SGR bold and reverse, and a palette tuned for a black background. The 8x8 `font8x8` path is used only by the panic screen.
- `FBIO_BLIT` (0x4642_0001): nearest-neighbour scaled, letterboxed full-frame blit (DOOM/Quake on the console). It sets `FB_RAW_DIRTY`, so the next text write clears the screen.
- **`kalert!("...")`**: one red line through the normal renderer, printed when a fault kills a process (`kill_current_user_process`). It uses **`try_lock` on `FB_STATE` and `FRAMEBUFFER`, never `lock`**, because the fault may have interrupted the lock holder. No heap formatting.
- Cursor blink runs in the tick with `try_lock`.
- `TIOCGWINSZ` reports cells, and `ws_xpixel`/`ws_ypixel` report the screen size in pixels.

## `/dev/fb0` — graphics mode (`drivers/dev_fb0.rs`)

- Exclusive: a second open gets `EBUSY`; no shadow means `ENODEV`.
- **Holding it is graphics mode**: the console keeps parsing and mirroring but draws nothing, the cursor stops, and `FBIO_BLIT` returns `EBUSY`. `kalert!` and the panic screen still draw.
- The mode ends in `Drop` of the last handle, so killing the holder gives the console back.
- `mmap(MAP_SHARED)` maps the **RAM shadow** through a pinned `ShmObject` (a static that is never freed), so it behaves as an ordinary shared mapping.
- ioctls: `FBIO_GET_INFO` (0x4642_0010; geometry + offset of pixel (0,0)) and `FBIO_FLUSH` (0x4642_0011; up to 16 rectangles). With page flipping, `FBIO_FLUSH` is a flip at the next vblank and returns `EBUSY` (nothing copied) while the previous one is pending, `EIO` if the display refused it (the rectangles were shown on the buffer on screen).
- Test: `fb0_test` (`fb0_test hold` keeps the picture up for a screendump).

## Compositor (`compositor`, crate `gui`)

- `compositor [prog...]`:
  - holds `/dev/fb0`, grabs `event0`, reads `event1`;
  - listens on `/tmp/gui-0`, all under one `epoll`;
  - quits with Ctrl+Alt+Backspace.

  With no arguments it starts a session with `panel`.
- **Disk-resident** (`/mnt/bin`): no `/mnt`, no compositor.
- The protocol is a minimal Wayland-named one (`gui` crate: wire format, regions, `Compositor` state machine, `compose` into a `&mut [u32]`: the CPU painter, which rasterises the same draw list as the GPU compositor, the theme's shapes included, with `gui::theme::Shape::paint`). The C side of the wire is tested against it by `gui/tests/c_wire.rs`.
- Children are started by `userspace::launch::spawn`:
  - a bare name is looked up in `/bin`, then `/mnt/bin`;
  - each child gets its own process group with default ^C/^Z;
  - fds ≥3 are closed before exec (there is no close-on-exec);
  - `GUI_DISPLAY` is set.

  Children are reaped with `syscall::reap_any`.
- The compositor ignores SIGINT/SIGTSTP; `^\` (SIGQUIT) still kills it.
- **Pacing.** With `/dev/vblank` (`gpu=vblank`, `docs/reference/gpu.md`) the RAM shadow is the back buffer: on each vblank it first `FBIO_FLUSH`es what the previous frame composed (the copy starts in the blanking interval and outruns the beam), then composes the next frame, so a change shows one frame after it is composed. The vblank fd is in the epoll set only while there is damage or a pending flush; a vblank missing for 50 ms (`VSYNC_GRACE_MS`) is not waited for. Without `/dev/vblank` (QEMU, `gpu=off`): at most one compose + flush every 16 ms, which the 100 Hz tick turns into 20 ms. With page flipping, an `EBUSY` flush keeps its rectangles; they are merged with the next frame's (bounding box past 16).
- `REL_Y` is PS/2-signed (up is positive) and is negated for the screen.
- **Window management** (`gui::compositor`, host-tested):
  - The compositor draws the decorations (title, close, maximize).
  - A client opts in with `set_resizable(min_w, min_h)`. Dragging the border sends **one** `resize` on release.
  - `resize` is a request: the old content stays until the client sends **any buffer created after the request**, whose size then wins.
  - `close` is sent to the client, never acted on by the compositor.
  - **F11 is the compositor's key** (never reaches a client, press or release): the focused window that sent `set_resizable` covers the whole screen without its title bar (and without a resize grip) and its client is asked (`resize`) for the screen's size; pressed again, it goes back to what it was, placed or maximized (`toggle_fullscreen`, `is_fullscreen`). It is composed like any window: the true direct scanout of its buffer (a `PRESENT` with no composition) is not done.
- **GPU buffers** (layer 4 of `docs/gpu/g5-graphics-stack-plan.md`; the model is done in `gui`, no host uses it yet): `create_gpu_buffer(id, fd, size, w, h, stride, format)` (compositor opcode 3) takes a descriptor of a client's GPU buffer. Off by default (`Compositor::enable_gpu_buffers`): the CPU compositor disconnects a client that sends one. The host takes `GpuOp::{Import, Drop}` (`take_gpu_ops`: every `Import` gets one `Drop`; free it once the frames started before are done) and composes from `draw_list()` (the whole screen, back to front, clipped: `Fill`, `Gpu`, `Cpu` for pool windows whose pixels `cpu_content` returns when `version` moves, `Title`, `Cursor`; a test rasterises it and compares it pixel for pixel with `compose`). A GPU buffer is **not** copied and **not** released at `commit`: it is released when a later commit replaces it *and* the host reported (`gpu_frame_done(epoch)`, frames in order) the frame that may have read it done; a buffer the client destroyed gets no release.
- **`gui-capi`** (`gui-capi/`, `include/gui_capi.h`): the window manager behind a C ABI. The GPU compositor no longer uses it (it is Rust and uses `gui` directly, below); it is kept for the host harness `probes/nvk/host-comp.sh` (a C program that drives the renderer). Handles, plain structs, events pre-encoded to the wire format, pool descriptors mapped inside; nothing blocks. A static library without std for musl (`cargo build --release --target x86_64-unknown-linux-musl --no-default-features`: the C library's allocator, abort on panic) and, with the default `std` feature, for the host test (`cd gui-capi && cargo test` compiles `tests/c_test.c` with `cc` and drives the whole API, checked by sabotage). The `gui_pop_*` calls drain the compositor first, so the others need not.
- **GPU compositor** (slice 3 of layer 4): `vk-comp/` (Rust with std on musl, a static library that exports `main`; `probes/nvk/build.py` links it with NVK and the renderer, `--allow-multiple-definition` for `rust_eh_personality`) is the machine: sockets, evdev, programs (the ones still running when it ends get SIGTERM, SIGKILL after 3 s; `COMP_F11_AT=60,120` presses F11 at those frame counts, a hook for QEMU), titles (the `text` crate, as `compositor.rs`), the window manager (`gui`); every frame it turns `Compositor::draw_list` into `cr_op`s (`probes/nvk/comp_api.h`) and calls the renderer. The renderer (`probes/nvk/comp_vk.c` = Vulkan bring-up and the `cr_*` entry points, `comp_render.h`, `comp.vert`/`comp.frag`) draws the ops back to front with one graphics pipeline, one rectangle per operation whose fragment shader shows a solid colour, reads the pixel of a client's buffer as a storage buffer, one for one (no sampler, no format), or computes a shape (`CR_SHAPE`: rounded box, gradient, border, drop shadow, from its signed distance). Every draw blends "over" premultiplied (opaque ones exactly replace); a buffer's `alpha` is opaque, keyed or premultiplied (`CR_PREMUL`). Push block 112 bytes, shared by `comp.vert`/`comp.frag`; after editing a shader run `probes/nvk/gen-spv.sh`. Plan for the looks: `docs/gui/compositor-visual-plan.md`. **Looks** (`gui::theme`): `draw_list` draws the desktop, decorations, taskbar strip and menu frame in the current `Theme` (`luna`, the default; `9x`) as `DrawOp::Shape`s (optionally clipped: `cr_shape.clip_*`) and fills; the geometry is the same in every look; **F12** cycles them (the compositor's key, like F11); vk-comp starts in `COMP_THEME` (default `luna`). Titles are premultiplied text over the bar (`CR_PREMUL`), in the colours `DrawOp::Title` carries. GPU buffers are imported where they are (opaque fd -> `VkBuffer`); pool windows are uploaded to a host-visible buffer when `version` moves; the cursor is a small buffer drawn with a colour key (top byte 0 = transparent). **One frame in flight**: a frame starts by waiting for the previous one, then `gui_gpu_frame_done` and the frees of dropped buffers, so uploads never race the GPU. Titles, windows' pixels and the cursor are CPU pixel sources (`CR_CPU`: uploaded when `version` moves, freed after 120 frames unused). Test with no Ryzen: `probes/nvk/host-comp.sh [dump-dir]` runs the real window manager (`gui-capi`) with in-process clients on the host's own Vulkan (`-DCOMP_HOST`: a client's "GPU buffer" is a memfd copied into a buffer every frame) and compares every frame pixel for pixel with a CPU rasterisation of the same draw list (frames: two windows, a swap of buffers and its release, a window dragged past the edge, a pool window that grows, the pointer in the corner, a client leaving, `5c-shapes`: shapes and premultiplied pixels drawn directly, `5d-luna`/`5e-9x`: both looks; every frame within 3 per channel, the shapes being floats on both sides); 12+ mutants of the original shader and renderer and 16 of the shape/alpha/clip path killed. On the cloud container: `apt-get install -y mesa-vulkan-drivers libvulkan-dev glslang-tools` (lavapipe).
- **`panel`** has the panel role: a bottom strip, never focused. It alone receives the `toplevel*` events and may `activate`. It is also told the compositor's look (`theme(name)`); in a theme with a taskbar the strip is the compositor's shape and the panel draws only its buttons, with the theme's shapes in software (`gui::theme::Shape::paint`), into a premultiplied `ARGB8888` buffer (pool buffers may be `ARGB8888`, wl_shm's 0: shown "over", by `compose` with `theme::over` and on the GPU with `CR_PREMUL`). Its "Apps" button opens the start menu, a **popup** (`set_popup`: above everything, undecorated, never focused; a click outside or Escape hides it and sends `popup_done`, the click going nowhere) with the apps and the theme selector (`set_theme`, the panel's alone); in a theme with a menu style the compositor draws the menu's frame and shadow under it. `panel: menu <label>@x,y` logs where its items are on the screen (`gui-e2e.sh wm` clicks them). Its launcher reads `/mnt/etc/gui/apps` (`name<TAB>command`, from `disk-image-root/etc/gui/`).

## Semantic tree (`gui::semantic`, backbone B5)

- What a window shows as nodes others can read: id (client's, non-zero, stable), parent (0: a root), role, flags (focused, selected…), actions, bounds (window pixels), `pos`/`set_size` (a virtualized list's row in the whole list), name, value. AccessKit's schema **mirrored** (the tree crosses the wire to a `no_std` compositor; `accesskit::Node` has no encoder without serde); `gui`'s tests check the role and action names against the `accesskit` crate (a dev-dependency only).
- Wire: `surface.semantics_node(node)` per node, parents first, applied at the next `commit` (a commit without nodes keeps the tree); at most `MAX_NODES` (4096) per commit, id 0 refused. `compositor.get_semantics(callback)` answers `semantics_window` (toplevel, title, content box on the screen, focus) + that window's nodes per window, bottom first, then `done`. Any client may ask (the socket is the boundary today); not yet exposed as files (P7.2).
- Both compositors get it from `gui::compositor`. Publishing: `ui` builds it (`State::render` → `Frame::nodes`), `gui_client::Window::set_semantics` sends it. Reading: `gui_client::semantics()`, and the program `gui-tree` (run it in `term`: one line per node, indented; `scripts/gui-e2e.sh ui` parses it). `panel`, `term` and the `gfx` clients don't publish one yet.

## Files (`files/`, `/mnt/bin/files`)

- `files [PATH]`: places (sidebar), path bar, the folder as a `ui` list (name, size, type, modified; folders first; `stat` only for rows shown), an inspector (details + preview). Keys: the list's, Enter opens (a folder; a file with `/mnt/etc/gui/open`: `extension<TAB>command`, the path added last), Backspace up, Space the full-window preview, Tab to the path bar. In the launcher's apps (`files /mnt`).
- **Preview layout per folder** (P2.3): right of the list, or under it (`ui` vertical split) when pictures are more than half the files (`files::entry::layout`); a selection never moves the list.
- **Previews** (P6.4): `files-preview` runs through `cap-exec --fd 3:read+seek+fstat --fd 4:write+seek+fstat` in capability mode with only the file (fd 3) and a memfd (fd 4) sized by `files::preview::capacity`. It answers by `pwrite` in the `FPV1` format (`files/src/preview.rs`: header, `key\tvalue` metadata, then premultiplied pixels fitted to 360×360, ≤ 200 lines of cleaned UTF-8 text, or why there is none); `files::preview::decode` bounds and checks every length, because the provider is untrusted. A selection held 120 ms starts one; moving on kills it; a crash, a non-zero exit (its stderr's last line), a refused answer or 5 s without one (`FILES_PREVIEW_TIMEOUT_MS`) is shown in the inspector with the reason (P1.1). Test hooks: `FILES_PREVIEW_TEST=sleep:MS|escape`.
- Logs every step (`files: at …`, `files: preview NAME: …`, pids) to stdout; redraws only when something changed. Tests: `cd files && cargo test` (entries, layout, open table, previews from real PNG/text bytes, a lying provider refused); `scripts/gui-e2e.sh files`.

## GUI client libraries

- **Rust**: `userspace::gfx` (`Gfx::open(GUI_DISPLAY, …)`, `present`, `next_event`, `resizable`, `size`, `EV_GFX`) plus the `draw` crate (software 2D, integer-only).
- **Rust with std** (new programs; `docs/userland/roadmap.md` step 6): the `gui-client` crate. `Window::open(title, Some((w, h)) | None)` (None: the compositor's suggestion, half the screen) connects to `$GUI_DISPLAY`; `frame()` gives the `w*h` `0x00RRGGBB` pixels, waiting for the compositor's `release` of the last frame (that paces the program); `present()`/`present_rect()`; `next_event(timeout)` gives `Event::{Key, Motion (window pixels), Button, RelativeMotion, Focus, Resize, Close}`; `set_resizable`, then `resize(w, h)` on `Event::Resize`; `lock_pointer`; `as_raw_fd()` for the program's own `poll`. No scaling (pixels are the screen's). Errors are `io::Error`s that say what failed (`GUI_DISPLAY` unset, connect, a compositor `error`, `UnexpectedEof` when the compositor goes). Same `gui::protocol`/`gui::wire` as everything else. Host tests against a fake compositor on a socket pair (`cd gui-client && cargo test`); in QEMU `scripts/gui-e2e.sh std` (its `hello-window`).
- **Widgets** (`ui` crate, `no_std + alloc`, used from std programs): the app builds a `Widget` tree every frame (label, button, single-line field, `List` with columns or in the sidebar style, image, column/row with `Size::{Fixed, Auto, Fill}`, split with a draggable handle (side by side, or `vsplit` one above the other), scroll area, named pane); `State` keeps focus, selections, scroll, field text and split positions, `handle(tree, size, Input, now_ms, measure)` gives `Action`s (clicked, selected, activated, changed, submitted, an unused key with the focus), `render` gives `Paint` ops + the semantic tree. Lists are virtualized: `row(i)` is called only for the rows shown, only by `render` (type-to-find scans the first column on a key press). Keyboard: Tab/Shift+Tab focus, arrows/Page/Home/End, Enter, type-to-find (1 s reset); pointer: click, double click (400 ms), drag the split, wheel. Looks: `gui::theme::Widgets` (each theme has one). Ids ≥ `DERIVED` are the rows' and headers' (hash of list id and row key; a collision in a frame is bumped). The `render` feature's `Painter` paints with the `text` crate and is the `Measure`. Host tests: `cd ui && cargo test` (fake metrics) and `--features render` (real Noto). No wheel events reach clients yet (the protocol has none). Example: `ui-demo/`.
- **C**: `userspace/c/include/constanos_gfx.h` (header-only).
- **Vulkan programs** (`userspace/c/include/constanos_gui_vk.h`, with `constanos_vk_window.h`): `gvk_open` connects and makes the surface, `gvk_surface_create` makes the `VkSurfaceKHR` over NVK's WSI (`docs/reference/gpu.md` "WSI windows"), `gvk_next_event` gives keys, the pointer and `GVK_CLOSE`. The program is the connection's only reader; the swapchain calls back into `gvk_pump`.
- With `$GUI_DISPLAY` set, the program runs in a window (integer-scaled into shared memory); otherwise it uses `FBIO_BLIT` + `event0`/`event1`.
- **HIDPI** (`gfx::HIDPI`, C `GFX_HIDPI`): the program draws at `w*scale × h*scale` itself. Use it for antialiased text; leave pixel art (DOOM, Quake, `fire`) without it.
- Games lock the pointer (`lock_pointer`/`relative_motion`): only while focused; Ctrl+Alt releases it, a click takes it back.
- **Proportional text**: `userspace::text` (crate `text`: parley + swash). `Text::load()` reads fonts from `/mnt/usr/share/fonts` and falls back to `draw`'s bitmap font. Programs linking it are ~1.2 MB larger, so they are disk-resident.
- **`term`**: pty + `busybox ash` as session leader (`TERM=xterm-256color`) + the `vt` crate (xterm grid, parser, renderer, keymap). It exits when the master reports EIO.
- **Images and alpha**: `userspace::img::load(path)` (crate `img`, over `zune-png`) decodes any PNG to **premultiplied `0xAARRGGBB`**; `Canvas::blit_over` composites it ("over", exact `/255` rounding, the destination's top byte kept). `draw::blend::over_row` runs AVX2 (8 px/step, all-transparent and all-opaque blocks short-circuited) when CPUID + XCR0 say so, else scalar; both give identical bits (`cd draw && cargo test`; `cargo test --release -- --ignored bench` for timings).
  - AVX works in userspace only because the kernel enables XSAVE (`process/fpu.rs`); a program must check `draw::blend::has_avx2()`, never assume.
  - Icons live on disk in `/mnt/usr/share/icons` (`disk-image-root/usr/share/icons`, synced by the root `build.rs`; the sync adds and overwrites, never deletes), never embedded. Layout like a freedesktop theme: `<n>x<n>/<name>.png` per size the artwork exists at, optional unsized `<name>.png` at the top.
  - **HIDPI**: `img::load_icon(name, size, gfx.scale())` wants `size * scale` pixels, picks the smallest themed size at least that big (else the biggest; `img::pick_size`), and resamples **once, at load** (`Image::resized`: separable Catmull-Rom in premultiplied space, stretched when shrinking so it averages instead of aliasing; results clamped to valid premultiplied). Every frame then blits it 1:1. Never resample per frame.
  - `imgview` (no args: the `sample` icon at several logical sizes; with files: each at its logical size × scale) prints the chosen source, load and blit times.
- Test end to end: `scripts/gui-e2e.sh [term|wm|text]` (screendumps + serial log).
