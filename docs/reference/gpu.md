# GPU (NVIDIA GA106) and its kernel prerequisites

Plan and decisions: `docs/gpu/gpu-plan.md`. This page is the current state. Pure logic: crate `nvgpu` (GPU) and `hal::pcicfg`/`hal::dma`/`hal::bootopts` (generic); kernel adapter: `kernel/src/gpu/`.

## Boot options (`kernel/src/bootopts.rs`, `hal::bootopts`)

- UEFI gives no command line. `key=value` words are read once after `fs::init` from `/mnt/etc/kernel.conf`, then `/mnt/autorun/kernel.conf` (later wins; `#` comments). Before that, everything is at its default.
- `/mnt/autorun/kernel.conf` is written by `scripts/metal-run.sh --kconf '...'` and removed with `autorun/`, so an option applies to one unattended run only.
- `disk-image-root/etc/kernel.conf` is gitignored: a checkout's own options.
- `gpu=` (`hal::bootopts::GpuLevel`): `off` (default: the GPU is not touched), `probe`, `disp`, `vblank`, `dispstate`, `chan`, `scanout`, `super`, `vpll`, `dplink`, `modes`, `hdmi`, `fwsec`, `gsp`. Each level does everything the previous ones do. An unknown value is logged and read as `off`.
- `disk-image-root/etc/` is not synced to `disk.img` (only `etc/gui` is). To try a level in QEMU, write the file into the image: `debugfs -w -R "write <file> /etc/kernel.conf" disk.img` (and `rm` it after).

## `gpu=probe` (phase 1)

`gpu::probe()` runs in `init::boot` after `logpart::init`, before the APs are released. Output goes to the log (`gpu: ...`) and `/proc/gpu`:
- the firmware files (size, first word, FNV-1a 64 to compare with the host's copy);
- D4: each IOMMU from the IVRS (`hal::acpi::parse_ivrs`), its control register and `IommuEn`;
- the GA106 (`10de:2507`): capabilities, MSI/MSI-X, BARs with sizes; BAR0 mapped UC and `PMC_BOOT_0` decoded (`nvgpu::id`); the first 16 MiB of BAR1 mapped WC (not accessed); `pci::claim(..., "nvgpu")`.
- **No GPU register is written.** The only writes are the BAR sizing protocol's, in configuration space, with decoding off for microseconds (no CPU may draw on the GOP framebuffer then: hence before the APs).
- Metal job: `scripts/metal-run.sh --kconf 'gpu=probe' scripts/metal-jobs/gpu-probe.sh`.

## `gpu=disp` (phase 2)

Everything `probe` does, then (`gpu::probe_displays`, only if `PMC_BOOT_0` says GA106):
- **VBIOS** from the PROM (`nvgpu::vbios::read_prom`: BAR0 `0x300000`, image chain by PCIR/NPDE like nouveau's `shadow.c`). The ROM-shadow bit (`0x088050` bit 0) is cleared only if set and restored; on the target it is already clear, so no write. `/proc/gpu` shows size, time, FNV-1a of the first 148 992 bytes (= the phase 0 dump), images and the BIT version.
- **DCB** (`nvgpu::dcb`): outputs (walk of `engine/disp/nv50.c`), CCB 4.1, connector table. Logged as nouveau prints them.
- **Connectors** (`nvgpu::display::connectors`): the connector-table entries some output uses. Name = DRM type + count per type in table order (nouveau's naming): `DP-1`, `DP-2`, `DP-3` (the ASUS, AUX 3), `HDMI-A-1` (the HP, I2C port 5). The proprietary driver calls the ASUS `DP-1`; these names are not Linux's `nvidia` ones.
- **Probe** by polling, no interrupts (`nvgpu::display::probe`):
  - DP: DPCD caps (+ the 0x2200 extended copy) and EDID blocks 0-1 by I2C-over-AUX (`nvgpu::aux`: `auxgm200.c` transaction + DRM's retry policy). No sink (AUX status bit 28) = disconnected.
  - HDMI: EDID by bit-banged I2C (`nvgpu::i2c`: nouveau's `bit.c` on `busgf119.c`'s port register). NACK at 0x50 = disconnected.
  - Pads (`nvgpu::pad`) switched to AUX/I2C and put back; the AUX auto-DPCD bit (nouveau leaves it cleared) is restored too.
  - More than one EDID extension is not read (needs the E-DDC segment pointer, never used in the trace): shown as a `note:`.
- `/proc/displays`: one line per connector (`name status conn N aux|i2c N  MFG name`), then `dpcd:`, `preferred:`, `range:`, `modes:` (every DTD), `edid-fnv1a64:` and `edid-hex:`.
- Runs before the APs are released; delays are TSC busy-waits that service TLB shootdowns.
- Metal job: `scripts/metal-run.sh --kconf 'gpu=disp' scripts/metal-jobs/gpu-disp.sh`.

## `gpu=vblank` (phase 3)

Everything `disp` does, then `gpu::vblank::setup` (still at boot, IF=0, before the APs):
- **Heads** (`nvgpu::vblank`): which exist (`0x610060`) and what each scans out, from its ARM state (`0x68a000 + head*0x400`: totals, blanking, pixel clock → refresh). A head with a clock and a raster is "lit"; the lowest lit one is the **primary**.
- Read-only evidence, logged before arming: the interrupt tree and display interrupt registers as the firmware left them; the primary head's raster position sampled for 200 ms (frames counted by vline wrapping: plan B's instrument); whether its vblank status bit latches (cleared, read 40 ms later).
- **Arming** (`nvgpu::vblank::arm`, nouveau's order): unarm the VFN tree (`0xb81610`), block every leaf, reset + allow only the display bit (leaf 4, `0x04000000`), MSK=vblank for every head (`0x611cc0`), EN bit 2 for the lit ones (`0x611d80`), MSI rearm (`0x088704`), rearm (`0xb81608`). Then PCI bus mastering on (MSI is a memory write; the GOP leaves it off) and MSI to CPU 0.
- **Handler** (`on_msi`, ISR on CPU 0, global work): `nvgpu::vblank::service`, the trace's handler register for register (unarm, MSI rearm, leaves, `PMC_BOOT_0` check, reset, `0x611ec0`, per-head ack of LOADV and VBLANK, rearm). Nothing else touches BAR0 after boot, and the GPU sends no second MSI before the rearm, so no lock. Leaf bits with no handler are blocked (nouveau's storm guard).
- Counters in `/proc/kdebug`: `gpu_vblank: enabled primary_head seq last_ns msi vector spurious blocked gone disp_other head_other`, plus `gpu_vblank_headN` per lit head. `seq`/`last_ns` are the primary head's vblank count and the `ktime_get` of the last one, so a rate needs no sleep precision.
- **`/dev/vblank`** (`drivers/dev_vblank.rs`): `ENODEV` unless armed. Readable (poll/epoll) once a vblank happened after the one the handle last read; `read` never blocks and returns 16 bytes (sequence number, ns). Blocking reuses poll's input-queue machinery (`evdev::QUEUE_VBLANK`; `EventSource::seen` carries the handle's number and the re-check compares it with the live one).
- `PollSource` is pinned at 16 bytes (`const` assert in `poll.rs`): `poll_wake_where` keeps 8 waiters with a 16-entry map each on the ISR's stack, and 24 bytes overflowed it.
- Metal job: `scripts/metal-run.sh --kconf 'gpu=vblank' scripts/metal-jobs/gpu-vblank.sh` (rate over 30 s must be 60.0 ± 0.1, then `compositor fire` for 20 s for a tearing photo).

## `gpu=dispstate` (phase 5.1)

Everything `vblank` does; before arming vblank, `gpu::read_dispstate` reads the display's ARMED method state (`nvgpu::dispstate`), with no writes:
- core: `0x688000 + method` for nouveau's 243 dumped methods (`gv100.c:610-705`); window 0: `0x690800 + method` for its 80 (`gv100.c:417-505`).
- `/proc/dispstate`: `gop:` (the GOP framebuffer's physical address as a BAR1 offset, compared with window 0's `SET_OFFSET` and pitch), `headN:`, `sorN:`, `window owners:`, `window0:` (surface), then one `core MMMM VVVVVVVV` / `wndw0 MMMM VVVVVVVV` line per method, to diff against `nvgpu/fixtures/modeset-core-round1.txt`.
- On the Ryzen (boot #69): identical to the trace's ARMED column except `UPDATE`; the GOP scans out BAR1 + 0, pitch 8192, context DMA handle `0x45564144`.
- Metal job: `scripts/metal-run.sh --kconf 'gpu=dispstate' scripts/metal-jobs/gpu-dispstate.sh`.

## `gpu=chan` (phase 5.2)

Everything `dispstate` does; then, before arming vblank, `gpu::evo::bring_up` (`nvgpu::evo`):
- **Instance memory**: 64 KiB of VRAM at `0x1ffc90000` (nouveau's address), written through PRAMIN (`0x1700` = VRAM >> 16, window at BAR0 `0x700000`; the base is put back). RAMHT at +0 (0x2000 bytes, 10-bit hash, `core/ramht.c`), context DMAs from +0x2000. One object: `0xfb000000` = all of VRAM, for window 0.
- **Display init** (`tu102_disp_init` minus ownership claim, interrupts and SOR power): capability copy into `0x640000`, `0x610078` bit 0, `0x610010 = 9` (VRAM, valid), `0x610014`.
- **Channels**: core (ctrl/user 0) and window 0 (1/1). Push buffers: 4 KiB `DmaBuf`s (below 4 GiB, else 40 bits), target HOST, kept forever (`PUSH`). Bus mastering is turned on here.
- **Gate** before each UPDATE: ASSEMBLY (`user_base + m`) = ARMED (`armed_base + m`) on every dumped method except the pushed ones and PRI-error reads (`0xbadf5xxx`). The core inherits ARMED; **a window starts with a reset ASSEMBLY**, so its differing methods are pushed with their ARMED values first, then the gate runs again.
- Pushes: core `SET_INTERLOCK_FLAGS = 0`, `SET_WINDOW_INTERLOCK_FLAGS = 0`, UPDATE; window 0 the restore + `SET_CONTEXT_DMA_ISO(0) = 0xfb000000` + interlocks 0, then UPDATE. The image is the same (the GOP framebuffer at VRAM 0, pitch 8192).
- **Faults** are polled, never enabled as interrupts: CTRL_DISP `0x611c30` (supervisors, error), EXC_OTHER/WIN/WINIM `0x611854/4c/50`, compared with what was there before. The per-channel exception slots are not zero at rest (`0x80`) and are only meaningful when an EXC bit is set.
- Report: `chan:` lines in `/proc/gpu` and the log, ending in `chan: OK: ...` or `chan: STOP: ...`. Afterwards both channels stay running and idle.
- Metal job: `touch build.rs` (the root build does not watch `nvgpu`), then `scripts/metal-run.sh --kconf 'gpu=chan' scripts/metal-jobs/gpu-chan.sh`. Ryzen boot #74: OK.

## `gpu=scanout` (phase 5.3)

Everything `chan` does; if `bring_up` ended OK (it returns window 0's PUT), `gpu::scanout::setup`, still at boot before vblank is armed:
- **Buffers**: two in VRAM at 16 MiB and 32 MiB (`BUF_VRAM`; = BAR1 offsets), one WC mapping of BAR1 [16, 48) MiB. Same layout as the GOP framebuffer (pitch 8192); STOP unless window 0's ARMED surface is the framebuffer's size and pitch, pitch-linear.
- **Attach** (`Framebuffer::attach_flip`): the RAM shadow is copied into both buffers, then a flip to buffer 0. Each boot flip is timed (`scanout: flip ...: fetched/armed/loadv/vblank +N us vline V`): when window 0 fetched the push, when its ARMED `SET_OFFSET` changed, when the head's LOADV and VBLANK status bits latched.
- **Proof**: the GOP framebuffer (VRAM 0) is then painted dark red. A red screen means window 0 still scans it.
- Two more flips (buffer 1, back to 0), then `scanout: OK: ...` or `scanout: STOP: ...`.
- **Flip** (`nvgpu::evo::flip`): `SET_PRESENT_CONTROL = 1` (non-tearing, nouveau's value; the GOP leaves 0), `SET_OFFSET(0) = vram >> 8`, UPDATE; PUT written, not waited on. Refused while the previous push is unfetched. The 4 KiB push buffer wraps with a JUMP to 0 then PUT = 0 (`evo::wind`, nouveau's `nv50_dmac_wind`).
- **Done** (`Scanout::flip_done`): GET = PUT, ARMED offset = requested, and (once vblank interrupts run) the vblank sequence moved past the one at submit. **ARMED changes within µs of the UPDATE, not at the vblank** (Ryzen #76); LOADV latches at the next vblank. So the vblank condition is what makes it a completion.
- At runtime `flip`/`flip_done` run under `FRAMEBUFFER` (from `FBIO_FLUSH`, any CPU, IF=1) and touch only window 0's PUT/GET/ARMED registers; the vblank handler never touches those, so BAR0 needs no lock.
- `/proc/kdebug`: `gpu_flip: submitted latched not_yet refused shown latency_us last max avg vblanks_per_flip sum max` (latency = submit to the first `flip_done` that saw it done: an upper bound).
- Metal job: `touch build.rs`, then `scripts/metal-run.sh --kconf 'gpu=scanout' scripts/metal-jobs/gpu-scanout.sh`. Ryzen #75/#76: OK, ~1000 flips in 20 s of `compositor fire`, none refused.

## `gpu=super` (phase 5.4)

Everything `scanout` does (needs `chan` OK); then `gpu::supervisor::setup`, at boot before vblank is armed:
- Reads heads/SORs present (`0x610060`), each DP/TMDS output's SOR by pad routing (`nvgpu::supervisor::route_get`, nouveau's `gm200_sor_route_get`), the primary head (lowest lit), the SOR driving it (ARMED `SOR_SET_CONTROL`), the GOP's DP link (`DpLink::read`: `0x612300`/`0x61c10c`) and the IED scripts a detach/attach would run. STOP unless that SOR runs DP with a routed DP output (only a DP attach is ported).
- Enables CTRL_DISP interrupts for the supervisors only (`0x611cf0`/`0x611db0` = 7; nouveau sets `0x187`).
- **Interrupt**: `nvgpu::vblank::service(m, true)` acks DISP_INTR bit 12 as `gv100_disp_intr_ctrl_disp` (pending → `0x611860`, error info from `0x611848`); `vblank::on_msi` then calls `supervisor::on_pending` (ISR, CPU 0, global work).
- **Work** (`nvgpu::supervisor::Supervisor::service`, `gv100_disp_super`): 1 reads head/SOR ARM+ASSEMBLY state, 1.0/2.0 run the output's `OffInt1/2`, 2.1 (clock change) is reported `ClockNotPorted` under `super` and programs the VPLL under `vpll` (below), 2.2 runs `OnInt2`, RG divider, DP audio symbols + watermark (nouveau's formula, GA102 has no `activesym`) and the SOR clock; non-DP attach is `AttachNotPorted` (5.8); 3.0 runs `OnInt3`. Heads not owned are released untouched (`Foreign`). Always releases (`0x6107ac+h*4 = 0`, `0x6107a8 = 0x80000000`).
- **IED scripts**: `nvgpu::init`, nouveau's VBIOS script interpreter with 9 opcodes (`NOT`, `GENERIC_CONDITION`, `SUB_DIRECT`, `COPY_NV_REG`, `NV_REG`, `DONE`, `RESUME`, `TIME`, `ZM_REG`); any other opcode stops the script (`ScriptError::Unsupported`). Enough for DP-3's scripts; HDMI's need more. `OffInt2` writes `0x21234`, which PRI-faults on this GPU (nouveau does the same; the PRIVRING leaf is blocked here).
- **`/dev/dispctl`** (`drivers/dev_dispctl.rs`): `write` `detach` / `attach` pushes `SOR_SET_CONTROL(sor)` = 0 / the GOP's value + UPDATE on the core channel (under `PUSH_AT`), not waited on; `EAGAIN` while the core is not idle, `ENODEV` on open unless set up and vblank armed. `read`: one status line (ARMED control, core PUT/GET).
- Report: `super:` lines in `/proc/gpu` (boot, then one per supervisor and per request, 64 kept) and the klog; `/proc/kdebug` `gpu_super: serviced=s1,s2,s3 script_errors not_done ctrl_disp_errors requests refused work_us`.
- Metal job: `touch build.rs`, then `scripts/metal-run.sh --kconf 'gpu=super' scripts/metal-jobs/gpu-super.sh`.

## `gpu=vpll` (phase 5.5)

Everything `super` does, with `Config::clocks`: supervisor 2.1 programs `VPLL<head>` for the ASSEMBLY pixel clock (`nvgpu::pll`, nouveau's `ga100_devinit_pll_set`).
- **Limits**: VBIOS BIT 'C' v2 → PLL table (this board: `0x4f51`, version 0x50, entry = type `0x80 + head`). VPLL0-3: refclk 27 MHz, VCO 800-1620 MHz, input 19-38 MHz, M 1, N 29-255, P 1-63. Only version 0x50 is parsed.
- **Coefficients**: P and M as `gt215_pll_calc` (P = VCO max / clock, M = 1); the VPLL runs at `refclk * (N + fN/8192) / (M*P)`, so N = whole part, fN = fraction × 8192 rounded. **Not nouveau's encoding** (N one lower, fN `- 4096`): measured on the Ryzen (#78/#79), nouveau's gives 147.15 MHz for 148.5. 148.5 MHz → N 55, fN 0, P 10, which is what the GOP leaves (`0xef18 = 0x370000`).
- **Writes** (`ga100.c:52-55`): `0xef00+h*0x40 = 0x02080004`, `0xef18 = N<<16|fN`, `0xef04 = P<<16|M`, `0xe9c0+h*4 = 1`.
- **`/dev/dispctl` `clock <kHz>`** (`0` = the GOP's): pushes `HEAD_SET_PIXEL_CLOCK_FREQUENCY` and `_MAX` (`0x200c`/`0x2028 + h*0x400`, Hz) + UPDATE; same raster, so only the refresh changes. `EINVAL` below 48 Hz on that raster (the ASUS's floor) or above what the GOP's DP link carries (lanes × rate × 8 / bpp: 180 MHz on its 2×HBR); nothing retrains the link.
- Report: `vpll:` lines at boot (limits, the GOP's clock's coefficients, bounds; the GOP's VPLL registers, read only); `dispctl` status adds ARMED pixel clock and VPLL0's `0xef18`/`0xef04`; `gpu_super: clocks_set=`.
- Metal job: `touch build.rs`, then `scripts/metal-run.sh --kconf 'gpu=vpll' scripts/metal-jobs/gpu-vpll.sh` (50 Hz for ~20 s, then back to 60).

## `gpu=dplink` (phase 5.6)

Everything `vpll` does; `supervisor::setup` also finds the output's DP table entry (`dplink::setup`, `nvgpu::dp::dpout_match`: BIT 'd', version 0x42 on this board; DP-3 = entry `0x6e96`, scripts BeforeLT list `0x6ef1`, AfterLT `0x67c6`, EnableSpread `0x733c`, DisableSpread `0x732b`, DisableLT `0x734d`, lnkcmp list `0x6ec1`) and logs `dplink:` lines.
- **`/dev/dispctl` `train <lanes> <rate>`** (rate in DPCD units, `train 4 0x14` = 4x HBR2): synchronous in the writer's syscall (~130 ms of busy-waits). Refused (EAGAIN) unless the SOR is detached: the ISR sets `LINK_FREE` at each supervisor 3 when the head's SOR drives nothing; any push but `detach` clears it; the check and `TRAINING` are under `PUSH_AT`, so no push happens during a training. EINVAL when refused before any SOR write (LTTPR present, config above sink/DCB, post-LT-adjust sink), EIO when the training ran and failed.
- **Sequence** (`nvgpu::dp`, nouveau's order, replayed against `trace-nogsp` write for write, `fixtures/dp-train.txt`): pad to AUX, LTTPR probe (`0xf0000`), receiver caps, `check_config`, DisableLT (nouveau's release), sink `DP_SET_POWER` to D0 (DRM read with its `0x102` probe), EnableSpread (writes `0x00e86c = 2`: the "unidentified" write of phase 5.0), BeforeLT + lnkcmp for the rate (SOR PLL search on `0x612488`, two 20 ms condition polls), `ga102_sor_dp_links` (40 ms), lane power, TPS1 then TPS2/3/4 with the drive table (`dpcfg_match`, `gm200_sor_dp_drive`), pattern off, AfterLT; pad back, auto-DPCD bit restored.
- `nvgpu::init` now also has `ANDN_REG`, `OR_REG`, `CR` (VGA CR at `0x6013d4/5`, byte accesses: `Mmio::rd08/wr08`), `CONDITION` / `CONDITION_TIME` (BIT 'I' condition table: 4 = `0x612488` PLL lock, 7 = SOR sequencer idle, 8 = `0x61c144` link ready), `ZM_MASK_ADD`, `AUXCH` and generic condition 5 (ASSR, DPCD `0x0d`); `Target::aux` is the output's AUX channel.
- AUX: nvkm's own accesses use the hardware retry loop (`Aux::nvkm_read/nvkm_write`, up to 33 sends on DEFER); DRM's don't (`native_read/write`, `drm_read` = probe + read).
- The next `attach` programs the DP packing for the new link (2.2 reads it back from the SOR); `clock`'s upper bound follows the trained link.
- `dispctl` status adds `link NxRATE[ef]` and `free 0|1`; `/proc/kdebug` `gpu_dplink: trains ok failed refused last_ms`.
- Not ported: LTTPRs, post-LT adjust, eDP rate tables, MST.
- Metal job: `touch build.rs`, then `scripts/metal-run.sh --kconf 'gpu=dplink' scripts/metal-jobs/gpu-dplink.sh` (4x HBR2, then back to the GOP's 2x HBR, at 1080p60).

## `gpu=modes` (phase 5.7)

Everything `dplink` does; then `gpu::modeset::setup` (boot, reads only): the EDID and DPCD `gpu=disp` read on the primary head's output's AUX channel, its modes, the size the head scans out now. Logged as `modes:` lines in `/proc/gpu` (every EDID mode and the CVT-RB2 ones at 48/60/75/100/120/144/165/180 Hz inside the range, each with its VPLL coefficients and DP packing on the max link; then the GOP's mode read back).
- **Modes** (`nvgpu::mode`): `Mode::from_timing` (EDID DTDs, progressive only), `cvt_rb2` (VESA CVT 1.2 RB v2 with integer arithmetic; = `edid-decode --cvt ...,rb=2` except where its float floor lands 1 kHz lower, e.g. 1080p50), `select` (first EDID DTD of that size whose refresh rounds to the request, else CVT-RB2 if inside the range descriptor's V rate and max pixel clock; its H limits are ignored: the ASUS's say 250-250 kHz, which its own DTDs violate), `Mode::methods` (nouveau's `nv50_head_atomic_check_mode` + `headc57d_mode` + `headc57d_or`: raster size, sync end, blank end/start, `0x2074 = 1`, `HEAD_SET_CONTROL = 0`, pixel clock and max, OR word with the polarities; = the trace's round-2 push for 1080p60), `Mode::from_head` (the inverse, for the GOP's).
- **`/dev/dispctl` `mode WxH@Hz`** (`modeset::set`, synchronous in the writer's syscall, IF=1): everything checked first (EINVAL: syntax, no such mode, **another size** (window 0, framebuffer, console and compositor keep theirs: not ported), no VPLL coefficients, no link carries it). Then, only if the current link cannot carry it (`lanes*rate*8/bpp` and `dp_config`): `detach`, wait for a new supervisor 3 (`LINK_FREE`), `dplink::train` to `nvgpu::dp::max_config` (nouveau's link: sink lanes/rate capped by the board's; 4x HBR2 on the ASUS). Then one core push with the mode's methods + `SOR_SET_CONTROL` = the GOP's value + UPDATE (`Cmd::Mode`); wait for supervisor 3 again (2.1 VPLL, 2.2 packing); ARMED raster/clock must equal the mode's. Waits bounded to 1 s each. **`set` runs with IF=1** (restored after): a syscall enters with IF=0, and on CPU 0 that blocks the supervisors' MSI until it returns (Ryzen #84). A mode identical to the ARMED one waits for no supervisor (the UPDATE raises none). No detach unless retraining: while detached the head raises no vblank (#83/#84); with the SOR attached a raster/clock change runs 2.0/2.1/2.2 by itself. A failure after the detach retrains the old link (if changed) and re-attaches at the old mode, then EIO. EAGAIN while another `set`/push/training runs.
- Going back down (e.g. to 60 Hz) keeps the faster link: it carries the mode, so no retrain.
- `dispctl` read adds a `mode:` line (connector, current mode or "the GOP's", size); `/proc/gpu` `mode:` lines per request; `/proc/kdebug` `gpu_mode: sets ok failed refused retrains last_ms current_mhz`.
- `clock`'s lower bound is now the current raster at 48 Hz (was the GOP's raster).
- Metal job: `touch build.rs`, then `scripts/metal-run.sh --kconf 'gpu=modes' scripts/metal-jobs/gpu-modes.sh` (180 Hz = the ASUS's DTD 4, 420.78 MHz, retrains to 4x HBR2; then 120 Hz CVT-RB2; then 60 Hz). Ryzen #85: OK (179.86, 119.93, 60.02 Hz).

## `gpu=hdmi` (phase 5.8)

Everything `modes` does; `gpu::evo::bring_up` also puts window 2's surface handle in the RAMHT, and `gpu::hdmi::setup` (boot, IF=0) finds the connected HDMI connector `gpu=disp` probed (the HP), its EDID and DCB output (07, TMDS), head 1 (must not be lit: the GOP lights head 0 only), window 2, a SOR nothing drives (SOR-0), the HP's preferred mode (EDID DTD 1, 1080p60, 148.5 MHz) and its VPLL coefficients; allocates window 2's push buffer, maps BAR1 [48, 64) MiB WC and paints the test picture (`nvgpu::pattern`: bars, ramp, steps, white border; text from `BASIC_LEGACY`). Logged as `hdmi:` lines. Nothing scans the picture until `hdmi on`.
- **`/dev/dispctl` `hdmi on`** (`hdmi::on`, synchronous, IF=1 like `mode`): SOR power if off (`nvgpu::hdmi::sor_power_up`, `nv50_sor_power`); window 2's channel (`init_channel`, once); pad route (`route_set`, `gm200_sor_route_set`: `0x612408 = 1`) and the HDMI encoder (`nvgpu::hdmi::enable`: GCP/ACR/ctrl `0x6f04c0..`, `0x616dc0`, SCDC off, AVI infoframe from the mode's VIC, no VSI; = `fixtures/hdmi-enable.txt`); `own_head` (the supervisors also work on head 1, route SOR-0 -> HDMI output); one core push (`nvgpu::hdmi::head_methods`: display id, `SOR_SET_CONTROL(0) = 0x102`, viewport, `Mode::methods`, usage bounds, dither, procamp, window 2's usage bounds and owner) + UPDATE; wait for supervisor 3 (2.1 VPLL1, 2.2 the TMDS OnInt2 script `0x5f10`, RG divider, SOR clock, 3.0); check ARMED; window 2's push (`window_methods` + `window_lut_methods`: surface, notifier, identity ILUT; interlocked with the core, `SET_INTERLOCK_FLAGS = 1`, window bit) + UPDATE, then the core push with the head's identity OLUT (`olut_methods`) and `SET_WINDOW_INTERLOCK_FLAGS` = the window bit + UPDATE, which releases both (Ryzen #89/#90: without the LUTs and the notifier the window UPDATE raised INVALID_STATE, slot `0x5080 0x1 0x2d`); wait for idle, check ARMED offset/ctxdma; faults; head 1's refresh by counting raster wraps (head 0 measured beside it as the instrument). Any failure runs `off` again.
- The LUTs (`nvgpu::lut`: 1024 identity entries + header, half-float for the ILUT) and the 4 KiB notifier area live in the HP's 16 MiB VRAM slot (`nvgpu::hdmi::ILUT_VRAM`/`OLUT_VRAM`/`NTFY_VRAM`); the RAMHT gets the window's surface/LUT/notifier handles and the core's LUT handle (`ramht_objects`, `gpu=hdmi` only). `supervisor::push_core` clears the core's window interlock flags on the push after one that set them (they persist in ASSEMBLY: a later core UPDATE would wait for the window: `hdmi off` did not latch, Ryzen #91).
- **`hdmi off`**: encoder disable (`nvgpu::hdmi::disable`), core push `SOR_SET_CONTROL(0) = 0` + display id 0 + UPDATE, wait for the supervisors, `disown_head`. Window 2 and head 1's raster stay configured.
- `nvgpu::init` gained `ZM_REG_SEQUENCE` (0x58: HDMI's lane setup `0x61c040..0x61c07c`); `supervisor::super_2_2` attaches TMDS (RG divider + `ga102_sor_clock` with `div2` above 340 MHz); both replayed against `trace-nogsp` (`round2_hdmi_attach_replays_the_trace_for_head1`).
- Not ported: audio (ELD, `0x616528` HDA device entry), HDMI 2.0 (SCDC scrambling), non-identity LUTs, size changes, the compositor on head 1 (the picture is static, written once at boot).
- `dispctl` read adds `hdmi: HDMI-A-1 'HP 2309' head 1 SOR-0 window 2 on|off mode ...`; `/proc/kdebug` `gpu_hdmi: enabled on ons ok failed last_ms refresh_mhz`.
- Metal job: `touch build.rs`, then `scripts/metal-run.sh --kconf 'gpu=hdmi' scripts/metal-jobs/gpu-hdmi.sh` (on 40 s, off, on 15 s, off). Ryzen #92: OK.

## Oracle tools (`scripts/gpu-trace.py`)

- `aux DIR CH` lists AUX transactions on a channel; `aux DIR CH SEL OUT` writes them as a `ReplayMmio` fixture (`nvgpu/fixtures/aux-ch3-dpcd-edid.txt`).
- `i2c DIR DRIVE` decodes bit-banged I2C from a trace (proved the port-register bits: it yields the HP's EDID byte for byte).
- `core DIR [N OUT]` decodes nouveau's core-channel dumps in dmesg (one per supervisor 1: ARMED `0x688000+m` → ASSEMBLY `0x680000+m`), naming each method from `clc67d.h` (needs `~/src/gpu-ref`).
- `disp DIR T0 T1` lists display writes labelled with the nouveau code that owns each range (`DISP_CLASSES`); `mem DIR LO HI T0 T1` lists non-zero writes into a mapped range (BAR3 instance memory).
- The display push buffers are in host memory on Ampere, so a `nogsp` trace has only their PUTs. `scripts/gpu-oracle.sh` mode `nogsp-vrampush` (`kms_vram_pushbuf=1`) puts them in VRAM behind BAR1, where mmiotrace sees them.
- `supers DIR T0 T1 [OUT]` extracts each supervisor service (from `R 0x6107a8` to the release) as a `ReplayMmio` fixture, minus other contexts' accesses (`SUPER_OTHER`): `nvgpu/fixtures/super-round1.txt`, `super-round2.txt`.
- `train DIR T0 T1 CH [OUT]`: every BAR0 access of a DP link training as a `ReplayMmio` fixture, minus PTIMER, other AUX channels and `TRAIN_OTHER(_TIMES)` (the HDMI encoder enable nouveau interleaves): `nvgpu/fixtures/dp-train.txt`.
- `push DIR [T0 T1 [OUT]]` decodes those push buffers (needs a `nogsp-vrampush` trace): one block per PUT write, each method named from `clc67d.h`/`clc67e.h`/`clc67b.h` (+ `EXTRA_METHODS`, the ones nouveau writes by number). Fixture: `nvgpu/fixtures/modeset-push.txt`.
- `core` and `push` name methods through `method_names(cls)`: header indices have no bound, so offsets are claimed index 0 first across all methods, then 1, …

## PCI configuration space (`kernel/src/pci.rs`, `hal::pcicfg`)

- `config_space` reads all 256 bytes (mechanism #1; no ECAM, so no extended capabilities). `hal::pcicfg::capabilities` walks the list, bounded.
- `size_bars`: Linux's sizing protocol, decode off, under one hold of `CONFIG`.
- `enable_msi(bdf, dest_apic_id, vector)`: single-vector MSI, INTx disabled; refuses without a LAPIC (8259 fallback). `hal::pcicfg::MsiCap::enable_writes` decides the writes, host-tested against the GA106's real config space (`hal/fixtures/ga106-config.txt`: MSI at 0x68, 64-bit, no masking, no MSI-X).

## MSI vectors (`kernel/src/interrupts/msi.rs`)

- 0x50–0x5F have stubs in the IDT from the start (it is a `Once`); `msi::alloc(handler)` hands one out, `free` returns it. Dispatch is a table of atomics, no lock; EOI after the handler.
- Handlers run in ISR context on the CPU the message targets: ISR rules apply, and the driver states whether its work is global or per-CPU.
- `msi::count(vector)`, `msi::stray()` for tests and diagnostics.

## DMA (`kernel/src/memory/dma.rs`, `hal::dma`)

- `DmaBuf::alloc(len, mask)`: zeroed, contiguous, power-of-two pages from the buddy; `bus_addr()` = physical (no IOMMU, D4); fails with `AboveMask` if the block is not under the device's mask (the buddy cannot allocate below a limit).
- `DmaPages::alloc(count, mask)`: non-contiguous 4 KiB pages (for radix3 tables).
- **Release is explicit** (`free`); there is no `Drop`, so a forgotten buffer leaks rather than being handed back while a device may still write it.
- Cacheable through the physical window (x86 DMA snoops).

## `gpu=fwsec` (phases 4a + 4c)

Everything `hdmi` does, then `kernel/src/gpu/gsp.rs::setup` at boot (IF=0, before vblank is armed): FWSEC-FRTS on the GSP falcon.
- **Falcon** (`nvgpu::falcon`, 4a): the GA10x DMA flavour only (`Falcon { base, addr2 }`, `GSP` = `0x110000`, bank 2 at `+0x1000`). `select`, `disable`/`enable`/`reset` (`ga102_flcn_*`, `gp102_flcn_reset_eng`: engine reset pulse `0x3c0` bit 0 held 10 us, scrub wait `0x0f4` bit 12 for 20 ms), `dma_wr` (256-byte transfers, `0x110/0x114/0x118/0x11c/0x128`, command `0x600 | 0x10 IMEM | 0x4 secure`, done = `0x118` bit 1 within 2 s), `load` (DMA IMEM secure + DMEM), `boot` (signature hints at `addr2+0x210/0x19c/0x198/0x180`, mailbox 0 = 0, boot vector, `CPUCTL = 2`, halt = bit 4 within 2 s, mailbox 0 must be 0), `gsp_reset` (`ga102_gsp_reset`, bits `0x111` of `0x1668`; not run by `fwsec`). PIO loaders are not ported.
- **FWSEC** (`nvgpu::fwsec`, 4c): BIT `'p'` v2 -> PMU table -> entry type `0x85` -> descriptor v3 in the VBIOS `0xe0` image (`Bios::slice` follows the image redirection). Image = IMEM `0xe100` + DMEM `0x800` bytes; 3 signatures of 384 B follow the descriptor's `0x2c` fixed bytes; `SignatureVersions` mask 7; engine `0x400`, ucode 9. `Fwsec::build` copies the image and patches the DMEM interface (id 4 "DMAP" mapper at DMEM+0x560: `init_cmd` `0x15` FRTS/`0x19` SB; command buffer at DMEM+0x7c0: `read_vbios` + `frts_region`). `prepare` (falcon probe, fuse register `0x8241e0`, `fwsec_signature_index`, signature patched at DMEM+`0x5a4`) then `execute` (reset, load, boot, verify `0x1438 >> 16` and read WPR2 `0x1fa824/8`).
- **Where FRTS goes** (`frts_region`): 1 MiB just below the VGA workspace, 128 KiB aligned: VRAM 8 GiB (`0x1183a4`), `0x625f04` bit 3 clear -> `0x1_ffe0_0000`. The trace's WPR2 low `0x01ffe000` is that `>> 8`.
- Adapter: DMA buffer below 2^40 (`DmaBuf`, freed only if the falcon halted; on a timeout it is leaked, the falcon may still read it). An already-set WPR2 (`0x1fa828 != 0`) is a `STOP`: FRTS would fail; power-cycle the GPU. Lines `fwsec:` in `/proc/gpu`, `gpu_fwsec: state=ok|failed wpr2_lo wpr2_hi sig ms code` in `/proc/kdebug`.
- Oracle: `nvgpu/fixtures/fwsec-frts.txt` (`trace-gsp`, 8,340-8,576 s, the polled status reads left out) and the VBIOS nouveau read in that boot; tests replay the whole sequence (fuse read to the LibOS mailbox writes) write for write.
- Metal job: `touch build.rs; scripts/metal-run.sh --kconf 'gpu=fwsec' scripts/metal-jobs/gpu-fwsec.sh`.

## `gpu=gsp` (phases 4d + 4e + 4f + 4g)

Everything `fwsec` does, and `gsp.rs::setup(.., full = true)` reads `gsp-570.144.bin` (**on the stick only**: `scripts/sync-usb-data.sh` decompresses it into `target/firmware/` and rsyncs it to `/mnt/lib/firmware/nvidia/ga106/gsp/`, protected from `--delete`; it does not fit `disk.img`), the bootloader and the booter and validates all of them **before FWSEC runs**, so a missing file stops with nothing changed. Then, in nouveau's order (`tu102_gsp_oneinit`/`tu102_gsp_init`):
- **Memory (4d, `nvgpu::gspmem`)**: `fb_layout` = the WPR2 plan from the top of VRAM down (VGA workspace, FRTS 1 MiB, bootloader, ELF, WPR heap, meta, 1 MiB non-WPR heap; this board: FRTS `0x1_ffe0_0000`, boot `0x1_ffdf_a000`, ELF `0x1_fc16_0000`, heap `0x1_f420_0000 + 0x7f0_0000`, WPR2 `0x1_f410_0000 + 0xbe0_0000`); `wpr_meta` -> the 256-byte `GspFwWprMeta`; `radix3` (level 0 -> level 1 -> level 2 -> the ELF's 15 513 pages, each a `DmaPages` page); `libos_args` (LOGINIT, LOGINTR, LOGRM, RMARGS, 32 bytes each) + `log_buffer_init` (page table after the put pointer); `rm_args` (`GSP_ARGUMENTS_CACHED`, `bDmemStack = 1` for r570); `shared_memory` (129 PTEs, command queue header at `+0x1000`, status queue at `+0x41000`). Every layout offset is asserted against a C compiler on the real headers: `nvgpu/gen/abi.c` (`nvgpu/gen/README.md`).
- **Quirk kept**: `heap_size_min` is 170 "MB" compared with bytes, so it never applies (nouveau's `tu102.c:272`; what the booter accepted).
- **FRTS** (as `fwsec`), then `Falcon::gsp_reset` and the LibOS address into the GSP mailboxes `0x110040/44`.
- **Booter (4e, `nvgpu::booter`)**: SEC2 = `Falcon { base: 0x840000, addr2: 0x1000 }`; `prepare` (fuse register `0x824148`, signature 0 patched), `execute` (reset, DMA load 0x8900 IMEM + 0x6200 DMEM, boot with the WPR meta's bus address in mailboxes 0/1 = `0xf7efe000/0` in the trace, mailbox 0 must be 0), `gsp_running` (`0x110080 = app_version`, RISC-V bit `0x111388 & 0x80`). Replayed write for write against `fixtures/booter-load.txt` (`trace-gsp`, 8,576-8,838 s; 235 DMA transfers).
- **RPC (4f, `nvgpu::rpc`)**: the queues are `Queues` over a `Shm` (cmdq = shared memory `+0x1000`, its TX header's write pointer at `+16`, read pointer in the status queue's RX header at `MSGQ+32`; entries of 4 KiB from `+0x1000` of each queue, 63 each; a message = 48-byte element header + 32-byte RPC header (`0x03000000`, `'CPRV'`) + payload, padded to pages, XOR checksum of its u64 words; one entry is kept free; the doorbell is any write to GSP `0xc00`). `SystemInfo` (928 bytes; offsets from clang `nvgpu/gen/sysinfo.c`; ACPI stub = `bValid 1` + three `0xffff`) and `registry` (3 dwords) reproduce nouveau's dumped payloads byte for byte (`fixtures/rpc72.bin`, `rpc73.bin`) and are queued before FWSEC as nouveau does. After the RISC-V check the adapter reads the status queue: **`RUN_CPU_SEQUENCER` (0x1002)** carries 420 register commands (reset the GSP core, DMA its bootstrap, start, wait for halt, `CORE_RESUME` = `gsp_reset` + LibOS mailboxes + SEC2 `0x130 = 2` + poll `0x1180f8` bit 26) that `run_sequencer` executes (addresses are validated before anything runs); other events are counted and dropped; `INIT_DONE` (0x1001) ends the wait. Then `GET_GSP_STATIC_INFO` (fn 65, a zeroed 1656-byte payload) and the reply's `gpuNameString` (offset 1260) gives the name. Oracle: `fixtures/{rpc-seq.bin,seq-ops.txt,seq-window.txt}` (the sequencer message, nouveau's own command trace, the register accesses of `trace-gsp` 9.858-9.877 s) and `rpc65reply.bin`.
- **RM objects (4g, `nvgpu::rm`)**: `alloc_request`/`control_request`/`free_request` build the payloads of `GSP_RM_ALLOC` (fn 103, 32-byte header), `GSP_RM_CONTROL` (fn 76, 24-byte header) and `FREE` (fn 10); the reply echoes the request with `status` filled (`check_alloc_reply`, `check_control_reply`, `status_error` = `r535_rpc_status_to_errno`). Parameter blocks: `NV0000` (120 bytes, `processID = ~0`), `NV0080` (56, `hClientShare` at +4), `NV2080` (4). The adapter's `Rm` struct (`kernel/src/gpu/gsp.rs`) does one RPC at a time (`call`) and `create_client`: root `0xc1d00000` -> device `0xde1d0000` -> subdevice `0x5d1d0000`, then `NV2080_CTRL_CMD_GPU_GET_NAME_STRING` (`0x20800110`) on the subdevice. Oracle: `fixtures/rm-{root,device,subdev,vaspace}-{req,rep}.bin` and `rm-ctrl801813-*.bin` (trace-gsp 10,109-10,110 s); the three ALLOC requests are reproduced byte for byte. `FERMI_VASPACE_A` (0x90f1) is phase 6 (below).
- Lines `gsp:` in `/proc/gpu`; `gpu_gsp: stage=memory|booter|riscv|init_done|name|objects|failed ... init_ms events name rm_name` in `/proc/kdebug`. After 4f the boot busy-waits (IF=0) a second or so for GSP-RM's init; continuation records (RPCs over 16 pages) are not ported.
- Lines: `gsp:` in `/proc/gpu`; `gpu_gsp: stage=memory|booter|riscv|failed booter_ms booter_mbox0/1 log_pp` in `/proc/kdebug`.
- Metal job: `touch build.rs; scripts/metal-run.sh --kconf 'gpu=gsp' scripts/metal-jobs/gpu-gsp.sh`.

## GSP firmware files (`nvgpu::firmware`, phase 4b)

Pure parsers, nothing sent to the GPU yet. Formats measured on the 570.144 files:
- `booter_*.bin`, `bootloader.bin`: `nvfw_bin_hdr` (magic `0x10de`) first. A booter has `hs_header_v2` + `hs_load_header_v2` (`Booter::parse` = `ga102_gsp_booter_ctor`): 2 signatures of 0x180 B, patch location, `meta` = fuse version 1, engine id 1, ucode id 3; IMEM = app 0, DMEM = OS data. The bootloader's header is `RM_RISCV_UCODE_DESC` (21 words, `Bootloader::parse`).
- **Which signature**: `Booter::signature_index(fuse_reg)` = `ga100_flcn_fw_signature` (`fuse_ver - fls(reg)`, register 0 = last). The register is `Booter::fuse_register()` (engine bit 1 -> `0x824140`, 4 -> `0x824100`, 0x400 -> `0x8241c0`, + `(ucode-1)*4`); `trace-gsp` reads `0x824148 = 1` for `booter_load`, so signature 0. `fwsec_signature_index` is FWSEC's *mask* variant (`ga102.c:114`, `trace-gsp` reads `0x8241e0 = 3`), for phase 4c.
- `elf_section`/`GspImage`: `.fwimage` (0x3c99000 B at file offset 0x40) and `.fwsignature_ga10x` (0x1000 B) of `gsp-570.144.bin`, bounds-checked (nouveau trusts the file).

## GPU page tables (phase 6a `nvgpu::mmu`, used by `gpu=vaspace`, 6b)

`PageTables::new(base, capacity, target)` builds a 5-level tree (PD3/PD2/PD1/PD0/PT, 4 KiB tables, 4 KiB pages) whose root is at physical `base`; `map`/`map_range`/`unmap`/`translate`; `images()` yields `(phys, [u8; 4096])` for the adapter to write to VRAM. `pte`/`pde` are the entry encodings (PTE aperture VRAM 0/host 2/non-coherent 3; PDE VRAM 1/host 2+VOL/non-coherent 3). RM side (`nvgpu::rm`): `vaspace_params` (externally owned), `vaspace_from_reply` (usable VAs from 64 MiB to 2^49), `set_page_directory_params` (`NV0080_CTRL_CMD_DMA_SET_PAGE_DIRECTORY` on the device). `map_huge`/`map_huge_range` (phase 6d) map 2 MiB pages: the PD0 entry itself is the PTE (`(pa >> 4) | flags`, in the FIRST qword of the 16-byte entry; a slot holds either a 2 MiB page or a table of 4 KiB pages, `MapError::Overlap` otherwise); `translate`/`unmap` handle both. PD0 is a 16-byte dual PDE with the **big**-page PDE first and the **small**-page PDE in the second qword (`PD0_SMALL = 8`; fixed 2026-09-29, it was reversed in boots #101-#104). Details and the format's sources: `docs/gpu/mmu-v3-notes.md`; evidence in `docs/gpu/gpu-plan.md` "Resultados de la fase 6a".

## `gpu=copy` (phase 6c, `kernel/src/gpu/copy.rs`, `nvgpu::chan`)

Implies `gpu=vaspace`. `vaspace::setup` calls `copy::prepare` (method buffer + two 4 MiB system buffers, `src` patterned) and `Buffers::map` (channel pages, VRAM destination, both buffers into our VA space) before writing the tables, and `copy::run` after `SET_PAGE_DIRECTORY`: channel `0xf1f00002` (class `0xc56f`, engine `0xb` = COPY2, runlist 1, privileged, instance/USERD in VRAM from 128 MiB), BIND, GPFIFO_SCHEDULE, copy object `0xc7b5`, then the ladder (release, VRAM->VRAM, system->VRAM, 4 MiB round trip). Submission: push buffer + GPFIFO entry written through PRAMIN, USERD `GP_PUT` (+0x8c), doorbell `0xbb0090` = `(runlist << 16) | chid` (RM's own token is for runlist 0; kept only as a fallback ring). Measured on the Ryzen (boot #105): every rung passes and the 4 MiB round trip is identical at ~6.1/6.4 GB/s (`docs/gpu/gpu-plan.md`, "Resultados de la fase 6c").

**Phase 6d** (evidence and numbers: `docs/gpu/gpu-plan.md` "Resultados de la fase 6d"):
- `kernel/src/gpu/bench.rs` runs at the end of `copy::run` (`bench:` lines of /proc/gpu, `gpu_bench:` in /proc/kdebug): PCIe link, size sweep, 16 x 4 MiB batches with 4 KiB and 2 MiB pages (both ~6.19 GB/s: the x8 Gen3 link is the ceiling), the CPU's `copy_nonoverlapping` + `sfence` into BAR1 (5.44 GB/s), rectangles of a 1080p screen (CE 2D vs CPU), CPU work overlapped with a copy (95 % free). Every copy whose data could be wrong is compared afterwards, and destinations are scribbled first (a check that passes on data an earlier copy left there proves nothing: boots #110-#117 had that bug).
- The fence of the benchmark and of the run-time path is a page of **host memory** (`chan::HFENCE_VA`, polled from cache); the ladder keeps the VRAM fence read through PRAMIN.
- `kernel/src/gpu/intr.rs`: interrupt sources besides the display, found by the leaf status a piece of work raises (`intr::discover`, `nvgpu::vblank::new_vectors`). The copy engine's non-stall interrupt (a launch with `chan::with_interrupt`, INTERRUPT_TYPE NON_BLOCKING) is **vector 7** (leaf 0, bit `0x80`; `0x104424 + inst * 0x80`, `ga100_ce_nonstall`). `vblank::setup` allows it (`arm_with`) and the MSI handler acknowledges it (`service_with`, `intr::on_serviced`, counters in `gpu_intr:`). GSP-RM raises **no** interrupt for its status queue.
- Run time (`copy::install`, `RUNTIME`): rings written through **BAR1** (`Bar1Io`, `VramIo` trait; no shared PRAMIN window), host fence; `/dev/dispctl` `copy irq <runs>` measures polling vs the interrupt (`gpu_copyirq:`), `copy fault` submits a copy to an unmapped VA (RM resets the channel; kills it, run last; `gpu_copyfault:`).
- `gsp.rs` keeps GSP-RM reachable after the boot (`Runtime`): `with_rm`, `runtime_name` (`/dev/dispctl` `gsp name`, ~460 us), `poll_events` (`gsp poll`), and `poll_events_isr` from the vblank handler every 6th vblank (`try_lock`; events are counted and logged with `rpc::event_name`, `gpu_gsprt:`). RM's events for a channel fault: `MMU_FAULT_QUEUED`, 5 x `POST_NOCAT_RECORD`, `RC_TRIGGERED`.
- **BAR1 after GSP-RM**: its boot rewrites `NV_PBUS_BAR1_BLOCK` (`0x1704`: `0x1fff00` -> `0x801f3f90`) so BAR1 no longer maps VRAM from 0 (stores lost, reads `0xbad0ac..`/`0xffffffff`); `gsp::restore_bar1` writes the firmware's value back after INIT_DONE (`gsp: BAR1_BLOCK ...` line). The compositor's `fb_flush` and the scanout buffers depend on it.
- Decision: the compositor keeps the CPU blit (CE +13.6 %, ~1.4 ms of CPU per full screen; revisit at >100 Hz, two monitors, or when `fb_flush` is the bottleneck).

## `gpu=compute` (phase 7a, `kernel/src/gpu/compute.rs`, `nvgpu::gr`)

Implies `gpu=copy`. `compute::prepare` (before the tables) reads `GET_CONTEXT_BUFFERS_INFO` on our subdevice (9 buffers, 12.8 MiB), lays them out at VRAM `0x1f0000000` / VA `0x3_0000_0000` (`gr::plan`), zeroes the ones RM initialises; `Compute::map` maps them (privileged, nouveau's page sizes) plus the GR channel's pages into our VA space. `compute::run` (after `copy`): the golden context as nouveau's `r535_gr_oneinit` — an RM-managed `FERMI_VASPACE_A` (`0x90f10001`) over a tree of our own tables (`gr::GOLDEN_TABLES`, buffers at the trace's VAs, `COPY_SERVER_RESERVED_PDES` naming its root/PD2/PD1), a privileged channel on GR0, `PROMOTE_CTX` with every buffer, a 3D object `0xc797`, all freed — then the GR channel (chid 1, runlist 0, BIND, GPFIFO_SCHEDULE, its own `PROMOTE_CTX`, compute object `0xc7c0`) and three rungs (semaphore release, 64 B inline to host memory, 4 KiB inline to VRAM in 1 KiB pushes). Measured on the Ryzen (boot #136): all three pass; `gpu_compute:` in /proc/kdebug.

### Phase 7b: a shader (`nvgpu::qmd`, `gr::{dispatch_push, l2_flush_push}`, rungs 4-6 of `compute::run`)

- `qmd::build(&Launch)` = QMD V03_00 (256 B, 256-aligned, `SEND_PCAS_A` takes it `>> 8`); `gr::dispatch_push` = `SET_OBJECT`, shared window `0xfe000000`, local window `0xff000000`, `INVALIDATE_SKED_CACHES`, `SEND_PCAS_A`, `SEND_SIGNALING_PCAS2_B` (3 = INVALIDATE_COPY_SCHEDULE), `WAIT_FOR_IDLE`, a class semaphore. The QMD's `RELEASE0` (one-word, `FE_SYSMEMBAR`) is the grid's own semaphore. Reference: Mesa `nak/hw_runner.rs` + `nak/qmd.rs` (`Qmd3_0`), `clc6c0qmd.h`.
- Shaders are SASS from the host's `nvcc -arch=sm_86` (`nvgpu/gen/shader/*.cu`, `extract.py`, fixtures `shader-{fill,copy,fillwt}-sm86.bin`, 0x180 B, 8 registers). CUDA ABI: kernel parameters from `c[0x0][0x160]`, cbuf 0 = 0x200 B. Code, QMD, cbuf 0, output page and semaphores live in three host pages at `gr::KERN_VA` (`KERN_*_OFF`), mapped `Target::Host`.
- Rungs: 4 `fill` -> host page (256 words from 8 CTAs x 32 threads, the other 768 words of the scribbled page must stay), 5 `fill` -> VRAM page then `copy` reads it on the GPU into the host page (`ld.global.cg`), 6 measures which CPU read paths (PRAMIN plain / +20 ms / MMIO L2 flush `0x70010`+`0x70000` / `MEM_OP_D L2_FLUSH_DIRTY` / `STG.E.STRONG.SYS`) show the SM's VRAM stores: **none does** (boots #137-#139), although FE/CE writes are visible through PRAMIN. `/proc/kdebug` `gpu_compute:` has `rungs`, `launch_host_us`, `launch_vram_us`, `grid_release`, `vram_cpu_view`.
- Verify SM-written VRAM from the GPU (a `copy` launch into a scribbled host page), not through PRAMIN, until the PRAMIN question is closed (`docs/gpu/gpu-plan.md`, "Resultados de la fase 7b").

## `/dev/nvgpu` (G4a: the interface for Mesa's NVK; plan `docs/gpu/g4-nvkmd-plan.md`)

- Contract: `nvgpu/uapi/nvgpu.h` (C), mirror `nvgpu::uapi` (layout and ioctl numbers checked against clang: `nvgpu/gen/uapi.c`). Bookkeeping and validation: `nvgpu::devmodel` (BOs, the GPU VA space with bind/unbind cuts, contexts, timelines, `EXEC` validation, behind a `Backend` seam; 36 tests, `nvgpu/mutations/devmodel.py`). Adapter: `kernel/src/drivers/dev_nvgpu.rs`.
- **Sessions** (G5 layer 1): each `open` is a session with its own `Device` (BOs, contexts, timelines), shared by `dup`/`fork` and ended by the last reference (killing the holder frees its part: unbinds, releases, forgets; the others never notice). Up to `hwq::SESSIONS` = 12 at once, the 13th `open` is `EBUSY`; `SLOTS` in `dev_nvgpu.rs` is the bit table, lowest free slot first.
  - **VA**: one set of GPU page tables, so each slot has a 16 GiB slice of `[64 GiB, 256 GiB)` (`hwq::session_va`; INFO's `va_start/va_end` are the session's). The model refuses addresses outside a session's slice, but the GPU does not enforce it: **no isolation between processes yet** (debt; the fix is one RM VA space + `PageTables` per session).
  - **VRAM**: one heap for every session (`VRAM` in `dev_nvgpu.rs`, `RangeAlloc` behind the `Backend::{shared_vram,vram_alloc,vram_free}` seam); INFO's `vram_used_B` is the whole heap's use.
  - **Channels** are the global `HW` state of `gpu/uapi.rs`: one GR channel per context (the boot's, then up to `MAX_RT` = 8 more: about 9 GR contexts across all sessions), one shared copy channel. `Backend::quiesce` at close waits only for **the closing session's** channels.
  - **Sharing buffers** (G5 layer 2): `NVG_IOC_BO_EXPORT` makes a descriptor (`BoFile`, `dev_nvgpu.rs`; an ordinary close-on-exec file, so `SCM_RIGHTS`/`dup`/fork carry it) and **returns it as the ioctl's result**; `NVG_IOC_BO_IMPORT {fd}` turns one into a BO of the importing session (new handle, same storage; a system BO maps with `mmap(devfd, mmap_offset)` in every session, a VRAM BO has none). The system arena (4 GiB `ShmObject`) and the VRAM heap are global (`STORAGE`), every allocation has a count of holders (its BO, each descriptor, each imported BO: `hold_storage`/`release_storage`), and the last one gives it back, discarding system pages *before* the range can be reused. So the exporter can free its handle or die first. Plumbing: `FileHandle::{ioctl_fd_arg, device_ref, ioctl_ex}` + `IoctlOut::NewFile` in `vfs` (a handle cannot reach the fd table, which `sys_ioctl` holds locked: `sys_ioctl` looks up the named descriptor and installs the new file). Mesa: `nvkmd_constanos` `import_dma_buf`/`export_dma_buf` (opaque fd and dma-buf share them); `probes/nvk/vk_share.c` runs it through Vulkan between two processes. Tests: `devmodel` (import/holders), `nvgpu_sw_test` (errors, lifetimes, EMFILE, SCM_RIGHTS), `nvgpu_hw_test` section 7, `vk_share`; sabotage `nvgpu/mutations/sharing_kernel.py` with `scripts/gpu-mutate-qemu.py` (one documented equivalent mutant: the `downcast` failure branch, unreachable while only `BoShare` has a `device_ref`).
  - **Sharing timelines** (explicit sync): `NVG_IOC_SYNC_EXPORT` / `SYNC_IMPORT`, the same descriptor mechanism (`SyncFile`/`SyncShare`; a BO descriptor is not a timeline and vice versa: `EINVAL`). `Device::sync_share` turns the session's timeline into one the *backend* keeps: in the kernel, a registry `SYNCS` of `{value, pending, queued signals (channel, fence seq, value), holders}`. A signal queued on a shared timeline (`EXEC`) goes there with its fence, and **whoever reads the timeline resolves the fences it finds complete** (`gpu::uapi::fence_done`, valid from any session), so the session that queued the work can be idle or gone. Work queued *before* the export (the order of a Vulkan program: submit, then `vkGetSemaphoreFdKHR`) is moved to the registry at share time (`sync_share`; found on the Ryzen #165: left in the session it was applied only when that session next called in, so an idle parent never completed it for its child). Channels resolve the registry before going (`resolve_all_syncs` in `ctx_destroy`), since an RT channel slot is reused. `/proc/kdebug` `gpu_share: sessions= storage_allocs= syncs= presenter=`: what sharing keeps alive, which must be 0 once everything is closed (the tests and the metal job read it). Mesa: `import_opaque_fd`/`export_opaque_fd` in `nvkmd_constanos`' `vk_sync_type` (`VK_KHR_external_semaphore_fd`, timeline and binary). Tests: `devmodel` (13 + 3 mutants on the share path), `nvgpu_sw_test`, `nvgpu_hw_test` section 8 (each process queues GPU work signalling a shared timeline and idles on a socket while the other waits on it and reads what that work wrote), `vk_share` (memory + timeline semaphore). Hardware-only mutants of the adapter (queued signals never resolved by a reader; a channel goes without `resolve_all_syncs`) are covered by section 8 on metal, not by QEMU (the software device completes at once).
  - **Run-time channel creation and destruction do not hold `HW`** for their RM part (Ryzen #163/#164): `prepare_rt` (locked, ~7 ms: slot, layout, tables, BAR1 span) then `run_rt` (unlocked: clearing the slot's VRAM through BAR1, then the RM calls, ~70-90 ms) then `finish_rt` (locked). With the lock held through all of it another client's `submit` stalled for the whole creation: a 178 ms hitch in a presenter's frame pacing when three clients started beside it; now the longest is 43 ms. `gpu_uapi:` has `create_us_max`, `prepare_us_max`, `destroy_us_max`, `lock_wait_us_max`. `ctx_destroy` is the same in three steps (count out and wait for idle with the lock taken per look; `take_rt` reserves the slot; RM frees unlocked; `finish_destroy_rt` unmaps): its RM frees held the lock up to 25-40 ms. After both, Ryzen #166: `lock_wait_us_max` 2.8 ms (144 ms at #163), a presenter beside three starting clients has 0 frame intervals over 25 ms (longest 20.1 ms, 60.1 fps). `/proc/kdebug` `gpu_uapi_slow:` lists the latest holds of `HW` over 2 ms (operation, when it let go on the `CLOCK_MONOTONIC` clock, how long, how long it had waited): what is left is `unbind` at 2.7-4 ms each and `ctx_create`'s `prepare_rt` (7.7 ms).
  - **Display**: the first session that `PRESENT`s owns the scanout; another session's `PRESENT` is `EBUSY` until the owner closes (which also puts the console's picture back). **`PRESENT` holds the storage it shows**: `Session::shown` keeps the latest buffer and the one it replaced (each a `hold_storage`; an accepted present means the flip before it took effect, so the older of the two is let go), released when the session closes after `restore_front`. So a client may free the BO it is showing (a WSI destroying its swapchain) without the display reading freed VRAM. Test: `nvgpu_hw_test` section 4e (metal only: the software device has no display; the job `gpu-multi.sh` requires its `ok` lines), sabotage = drop the `hold_storage` (Ryzen #171: `release of storage nobody holds` and a kernel panic in `devmodel` later in the run).
  - **WSI** (G5 layer 3, `VK_KHR_swapchain`; Mesa's `wsi_common_headless.c`, patched in `mesa-port/patches/`): on constanos the `VK_EXT_headless_surface` **is the screen** when the pdev read a display layout (`SCANOUT_INFO` at pdev creation, XRGB8888 only): `currentExtent` = the display's size, formats B8G8R8A8 UNORM/SRGB, FIFO only, `minImageCount` 3, opaque. Images are `wsi_common`'s buffer-blit swapchain (`WSI_IMAGE_TYPE_CPU` parameters, never DRM/dma-buf): `vkCmdCopyImageToBuffer` into a VRAM buffer with `pitch_B` rows, then `queue_present` waits the throttle fence (the copy is done), `wait_flip` (`nvk_constanos_wait_flip`: `poll(/dev/vblank)`), `PRESENT`. `acquire` never hands out the image on screen (`last`) nor, while a flip is pending, the one it replaces (`prev`): three images always suffice. No display (QEMU's software device) = plain headless, no size, nothing presented. The hooks are `wsi_device.scanout` (`nvk_wsi.c`). Apps know nothing of `/dev/nvgpu`: `snake3d` is the first (`probes/nvk/vk_snake.c`; `vk_draw` still calls the `nvk_constanos_*` extension).
  - **WSI windows** (G5 layer 4, slice 2; `userspace/c/include/constanos_vk_window.h`): a program that owns a connection to the compositor makes a surface of it with `nvk_constanos_surface_create(instance, &hooks, &surface)` (`hooks` = `new_id`, `send_buffer`, `commit`, `destroy_buffer`, `pump`; `constanos_gui_vk.h` implements them over `constanos_gui_wire.h`) and uses `VK_KHR_swapchain` as anywhere: FIFO, B8G8R8A8, any size up to 8192, 3 to 8 images. Every image is the buffer-blit swapchain's VRAM buffer (`wsi_create_buffer_blit_context` with the OPAQUE_FD handle type), exported (`vkGetMemoryFdKHR` = `BO_EXPORT`) and sent with `create_gpu_buffer`; a present waits for the copy's fence and only then `commit`s; an image is the program's again at the compositor's `release`, which the program's event loop passes on with `nvk_constanos_surface_buffer_released(surface, id)`; an acquire with every image held calls `pump(10 ms)` until one comes back (the program is the connection's only reader). A surface is a headless surface (`struct wsi_headless_surface`, one allocation, `window` set); the buffer ids come from the program's counter and are never reused. Test: `gui_fake_comp` (a stand-in compositor that imports every buffer with `BO_IMPORT` and checks the protocol and the release discipline) runs `vk_window` in QEMU: `scripts/run-abi-suite.sh gui_fake_comp`. The pixels are not checked there (VRAM is not mappable, the software device draws nothing).
  - **WSI limits**: a second client's frames are dropped (`PRESENT` `EBUSY`: one owner until the compositor, layer 4); QEMU cannot test the scanout path (software device has no display), only headless.
  - Tests: `devmodel` (shared-heap tests), `hwq` (slice arithmetic), `nvgpu_sw_test` (two sessions, slots full = `EBUSY`, reuse), `nvgpu_hw_test` section 6 (four processes at once, each launching compute), sabotage `scripts/gpu-mutate-kernel-sessions.sh`; metal job `scripts/metal-jobs/gpu-multi.sh` (`vk_draw` owner + three side draws + a second presenter refused).
- **System memory is one 1 GiB `ShmObject` arena** per session (`ShmObject::with_limit`, `discard`): a system BO is a range of it, `mmap(fd, bo.mmap_offset)` maps it, `BO_FREE` gives the pages back (a reused range reads as zeros). VRAM BOs have no CPU mapping (BAR1 is write-only after GSP-RM: `bar_size_B = 0`).
- **The kernel never blocks in an ioctl**: `SYNC_WAIT`, and an `EXEC` whose waits are not ready, return `EAGAIN` (`sys_ioctl` holds the fd-table lock across the call). Blocking is planned in the G4 doc.
- **Two devices behind one interface** (`KernelBackend::hw` in `dev_nvgpu.rs`). The **software device** (`NVG_INFO_SOFTWARE`, no `gpu=uapi` or no GPU: QEMU): everything is real except execution, which completes at once. Test: `userspace/c/nvgpu_sw_test.c`. The **hardware device** (`gpu=uapi`, G4c): see below. `nvgpu_hw_test` runs on both (on the software one it skips every check about what the GPU did).

### `gpu=uapi` (G4c: the hardware behind `/dev/nvgpu`, `kernel/src/gpu/uapi.rs`, `nvgpu::hwq`)

- Level above `compute` (`hal::bootopts::GpuLevel::Uapi`). `vaspace::setup` builds the tables with a pool of `uapi::POOL_TABLES` = 8192 tables (VRAM `[64 MiB, 96 MiB)`; 128 without `gpu=uapi`) and, when `compute::run` succeeded, hands them and the GR channel (`compute::Channel`: doorbell token, `GP_PUT` position, the host page) to `uapi::install`. `uapi:` lines in /proc/gpu, `gpu_uapi:` in /proc/kdebug (`state`, `spans_bar1/pramin`, `binds`, `unbinds`, `pages_bound`, `tables_written`, `tlb_flushes`, `tlb_us_max`, `execs`, `again`, `fences`, `dead`).
- **Buffers.** The user VRAM heap is VRAM `[1 GiB, 7.5 GiB)` (`hwq::USER_VRAM_*`; the GR context buffers start at 7.75 GiB). System BOs are frames of the session's shm arena (`ShmObject::frame_for_mapping`, one reference per mapped page, given back by `shm::unpin_frame` on unbind). `bind` = `hwq::bind_range` (4 KiB pages; all or nothing), then the tables it touched (`PageTables::take_dirty`: every table written or allocated since, empty ones included, because the pool's VRAM is never zeroed) are written to VRAM and the TLB is flushed (`hwq::tlb_flush_regs`: `0xb830a0/a4/b0`, ALL_VA | ALL_PDB, poll bit 31; `tu102_vmm_flush`, NVIDIA's `dev_vm.ref`).
- **CPU writes to VRAM** at run time go through BAR1 write-combined spans (`tables` = the pool, `channel` = `gr::VRAM_CHAN` + 64 KiB), each checked at install by storing through BAR1 and reading through PRAMIN; a span that fails is served by PRAMIN instead (`spans_pramin`). BAR1 is write-only after GSP-RM boots: nothing reads VRAM through it.
- **Two channels** (G4d). Contexts with compute [+ 3D] [+ copy] share the GR channel (chid 1) `compute::run` built (compute object, plus a 3D object for NVK's MME indirect dispatch); a copy-only context (NVK's upload queue) runs on the copy channel (chid 2, `copy::take_for_uapi`) and gets `chan::bind_push` (`SET_OBJECT`) before each submission, as NVK never binds the class. `ctx_create` refuses 2D/M2MF (`EINVAL`); copy commands pushed to the GR channel would fault it (no copy object there). Measured: NVK runs a compute dispatch (Ryzen #145). `EXEC` = one GPFIFO entry per push segment (`NO_PREFETCH` = `GP_ENTRY1_SYNC_WAIT`) + one entry running the kernel's **fence push** (`gr::fence_push`: `SET_OBJECT`, `WAIT_FOR_IDLE`, release of the sequence number into a semaphore in host memory, `gr::HOST_VA + HOST_SEM_OFF`) from one of 64 slots in the channel's push page. `hwq::Queue` does the ring arithmetic: the semaphore (32 bits) is extended to the 64-bit sequence numbers, and the entries the GPU consumed are known from the fences (nothing reads USERD). Ring or slots full = `EAGAIN` (`Error::Again`), nothing changed.
- **Failure.** No fence for 10 s with work in flight = the channel is dead (`kalert!`, `dead=1`): the next `EXEC`/`bind` is `EIO`, every fence reads as done (waiters drain), `open` refuses (`EIO`), and the memory the session bound is leaked on purpose (`leak`), because a wedged GPU may still write to it. Closing the device waits up to 3 s for the GPU to go idle (`Backend::quiesce`) before unbinding; if it does not, the same leak.
- Not done: other engines per context, a channel per context, recreating a channel after RC, blocking waits, 64 KiB/2 MiB pages, real `tpc_count`/`mp_per_tpc` (INFO keeps the software numbers: sm 86, 3 GPCs, 10 TPCs).
- Tests: `nvgpu::hwq` (30 host tests, mutation list `nvgpu/mutations/hwq.py` + `mmu_dirty.py` + `gr_fence.py`, one documented equivalent mutant), `nvgpu::qmd` (the C headers `userspace/c/nvgpu_qmd.h`/`nvgpu_shaders.h` against Rust and the clang oracle), `userspace/c/nvgpu_hw_test.c`, job `scripts/metal-jobs/gpu-uapi.sh`. Shader header: `scripts/gen-nvgpu-shader-header.py`.
